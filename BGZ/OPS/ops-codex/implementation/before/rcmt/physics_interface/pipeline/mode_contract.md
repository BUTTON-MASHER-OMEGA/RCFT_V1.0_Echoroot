# **Mode Contract (MC‑1.0)**
*(RCMT → RCF‑compatible, RCP‑typed)*

This contract defines what a **mode** is in RCMT, how modes arise from survivors, how they persist upstream, and how projection is allowed to interpret them downstream.

Modes are **upstream structural patterns**, not geometric waves, not fields, not excitations, and not ontological objects.

---

## **1. Purpose**

> **Define the upstream semantics of modes, their stability criteria, and the interface they expose to projection.**

Modes provide the structured patterns that projection interprets as spin, charge, harmonics, or field‑like excitations.

**Type:** Purpose
**Owner:** RCMT mode module

---

## **2. Ownership**

The mode module owns:

- the definition of mode structure
- the classification of mode families
- the upstream semantics of mode persistence
- the interface for mode exposure to projection

The mode module does **not** own:

- geometric interpretation
- field‑like interpretation
- wave‑like behavior
- continuous manifolds
- downstream harmonic structure

**Type:** Invariant

---

## **3. Mode Definition**

A **mode** is:

> **a stable, repeatable structural pattern within a survivor or geometry candidate that persists across evaluations and supports projection‑level interpretation.**

Modes:

- arise from survivors
- persist under LCO coherence
- maintain internal structure
- carry spin‑compatible orientation
- support harmonic‑like downstream behavior

Modes are **not** waves or fields upstream.

**Type:** Invariant (category definition)

---

## **4. Mode Families**

Modes may be grouped into families based on:

- adjacency‑stable patterning
- spin‑compatible orientation
- survivor‑internal structure
- geometry‑candidate compatibility
- projection‑level interpretability

Examples (non‑canonical):

- **orientation modes**
- **boundary modes**
- **internal survivor modes**
- **propagation‑compatible modes**

These families are **labels**, not ontological categories.

**Type:** Observation

---

## **5. Allowed Inputs**

The mode module consumes:

- survivor structures
- geometry‑candidate structures
- spin‑profile data
- adjacency signatures
- LCO coherence scoring

**Type:** Dependency

---

## **6. Allowed Outputs**

The mode module exposes:

- mode identity labels
- mode‑bearing structural patterns
- adjacency‑stable mode signatures
- spin‑compatible orientation profiles
- projection‑compatible structural variation

These outputs:

- **are upstream structures**,
- **may be interpreted by projection as spin, charge, or harmonic behavior**,
- **but are not geometric or field‑like on their own.**

**Type:** Interface Output

---

## **7. Mode → Projection Interface**

Projection may interpret mode outputs as:

- spin‑like behavior
- charge‑like behavior
- harmonic‑like excitations
- field‑adjacent variation
- geometric‑lane structure

These are **downstream interpretations**, not upstream facts.

**Type:** Downstream Interpretation

---

## **8. Prohibitions**

Modes must not:

- define geometry
- define fields
- define waves
- imply continuous manifolds
- introduce metric structure
- redefine survivor behavior
- widen upstream invariants
- imply mechanism or causality

**Type:** Prohibition

---

## **9. Scope Binding**

All mode statements must be scoped:

- “within the present formalism”
- “as upstream mode structure”
- “prior to projection”
- “in the mode module”

This prevents downstream leakage.

**Type:** Contract

---

This is observational, not canonical.

**Type:** Observation
