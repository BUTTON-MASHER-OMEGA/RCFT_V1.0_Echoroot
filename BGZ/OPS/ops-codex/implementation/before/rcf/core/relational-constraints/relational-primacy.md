## Statement

No system element possesses **intrinsic properties, state descriptors, or identity** independent of its relations.

All properties are **relationally instantiated** at boundaries, interfaces, or interactions.

---

### Formal Meaning

A system is characterized solely by:

* relational adjacency
* interaction strength
* constraint structure
* memory persistence

There is no requirement for:

* intrinsic essence
* absolute labels
* observer-independent attributes

Re-cutting boundaries may change descriptions, but **does not alter coherence**.

---

### Diagnostic Use

To evaluate a model or claim, ask:

* Which relations perform the explanatory work?
* Which properties vanish if relations are removed?
* Which descriptions depend on a particular boundary choice?

If an explanation relies on “what something *is*” rather than “how it relates,”
it violates this constraint.

---

### Failure Modes Prevented

* **Ontological reification**
  (turning glyphs, variables, or labels into entities)
* **Hidden absolutism**
  (smuggling intrinsic properties into relational descriptions)
* **Mythification drift**
  (symbols becoming entities)
* **Observer magic**
  (states existing because they are named or referenced)

---

### Compatibility Notes

This constraint is compatible with:

* Relational interpretations of physics (e.g., RQM)
* Interface-first design principles
* Systems and control engineering frameworks

---

### Downstream Dependence (Non-Normative)

* local-only measurement framings

These dependencies **do not justify** the constraint; they merely rely on it.
